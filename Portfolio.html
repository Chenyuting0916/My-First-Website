工作案例

每一件都是既有系統上的修改：問題是什麼、我動了哪裡、數字變成多少。

三件修改

75,000 → 50

Checksum 不一致，造成一天約七萬五千次多餘的 fallback

問題

checksum 對不上時，系統會再打一次 fallback API。這類呼叫一天大約 75,000 次，其中多數並不是真的需要。

做法

找出並修復 checksum 不一致，讓 fallback 只在真的需要時才發出。

結果

這個 fallback API 的每日呼叫從約 75,000 次降到 50 次以下，大約少了 99.9%。

10×

回應超過 2 秒的 API，拉到大約 200 毫秒

問題

有些 API 要超過 2 秒才回應。使用這些介面的人會停下來等。

做法

只改量測上真正超過 2 秒的那幾支。

結果

這幾支改善後大約 200 毫秒。以超過 2 秒對上大約 200 毫秒，大約快了十倍。

改得動

維修公告的計算拆開之後，才敢改

問題

公告的計算和服務寫在一起，時間也不好替換，所以站點資料彙整、時間區間合併和快取不好單獨測。改這段邏輯幾乎只能靠手動對。

做法

把計算和服務分開，注入時間，並為資料彙整、區間合併和快取補上測試。

結果

區間合併和快取可以單獨測試，原本會失敗的測試也修好了。同一時期，這批單元測試從 41 個補到 400 個以上，覆蓋彙整、合併和快取。測試變多是拆開之後的結果，不是目標。
